## 三、修复清单

| # | 问题 | 根因 | 修复 | 严重度 |
|---|---|---|---|---|
| 1 | 商品图 `/uploads/**` 全线 404 | 上传目录按**进程工作目录**解析：从 `HiddenWhite-backend/` 启动写到 `backend/data/uploads`，从仓库根启动写到 `<repo>/data/uploads`，而库里记的是同一个 URL；静态映射又独立拼了一次路径 | `ImageStorageService.root()` 按**模块根**（从 code source 反推）解析并缓存，`WebConfig` 静态映射改用同一入口；启动日志打印绝对路径 | P0（运营可见） |
| 2 | 未支付订单取消后积分/成长值不回收 | 积分在下单事务 `saveOrder` 里发放，与「是否收到钱」无关 | 移到 `markPaid`（状态真正推进到 `PAID` 后）发放，条件更新保证幂等，重复回调走幂等分支不重复累加 | P1（资损） |
| 3 | 管理端订单列表的「取消原因 / 支付信息」永远空白 | `CoffeeMapper.pageOrders` 只查 `status/note/completedAt`，而 `Orders.vue` 渲染 `row.cancelReason` | 补齐 `cancel_reason` / `cancelled_at` / `pay_channel` / `transaction_id` / `paid_at` / `refund_id` / `refunded_at`。`TIMEOUT_UNPICKED`（已收款未取餐）此前**看不出来**，会漏退款 | P1（漏退款） |
| 4 | 超时扫描随活跃订单量线性膨胀 | `findExpired` 把全部进行中订单读进内存再逐条过滤 | SQL 增加 `created_at < now - 最短有效期` 下界（阈值取自 `OrderStatus.TIMEOUT_BUFFER`，仍单一来源） | P2（性能） |
| 5 | UTC 服务器把「营业中」判成未开门 | `ShopRepository` 里 `LocalTime.now()` 用的是 JVM 默认时区，同文件另处却用 `LocalDate.now(ZONE)` | 统一为 `LocalTime.now(ZONE)` | P2 |
| 6 | 营业时段保存偶发写库失败 | 校验用 `trim` 后的值，写库用原始字符串 | 校验时规整成新列表，落库用同一批值 | P2 |
| 7 | 日客流补结算每晚无条件重算 7 天 | 任务注释说「补未结算日期」，实现却很直接地全量 `settle` | 新增 `OperationService.isSettled`，跳过已冻结日期 | P3 |
| 8 | 换账号登录后新会员首单减免被吞 | 退出登录只清内存 `shop.order/history`，storage 里旧订单仍在，冷启动被读回 → 首单判定认为「已下过单」 | 新增 `clearOrderState()` 同时清内存与 storage，退出登录与未登录刷新都走它 | P2（体验/资损） |
| 9 | 详情页在无 `id` 或规格为空时崩溃 / 展示幻影商品 | `product = ref(productData[0])` 用 mock 顶替；`sizeOptions[i].price` 无空值保护 | 商品为空即提示并返回菜单；规格与加购全部空值兜底；模板加空态分支 | P2 |
| 10 | 「仅告知」弹窗出现空白按钮 | 用 `cancelText: ''` 表达「只有一个确认键」，小程序把空串当有效文案 | `showConfirm` 支持 `showCancel`，调用方改用它 | P3（UI） |
| 11 | 导出在 Firefox/Safari 偶发「提示已导出但没文件」 | `URL.revokeObjectURL` 紧跟 `click()` 同步执行 | 延到下一轮事件循环释放 | P3 |
| 12 | dev profile 无法用环境变量关闭「跳过支付」 | `application-dev.yml` 硬写 `dev-mode: true` | 改 `${HW_PAY_DEV_MODE:true}`（缺省仍为开，可被环境变量关掉） | P2 |
