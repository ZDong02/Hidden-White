## 二、每次改动必过的闸门

改完就跑，**不要等 CI 告诉你**。下面命令按改动范围选，跑通才提交。

### 2.1 后端有改动

```bash
cd HiddenWhite-backend && ./mvnw test
```

### 2.2 管理端有改动

```bash
cd HiddenWhite-admin && npm run test:unit && npm run build
```

### 2.3 点单端有改动（最重的闸门，别省）

```bash
cd HiddenWhite-front
npm test && npm run lint
npm run build:h5 && npm run build:mp-weixin
```

### 2.4 动了图标或令牌（点单端 UI 任何改动都会落到这两处）

```bash
cd HiddenWhite-front && npm run assets:icons && npm test
```

### 2.5 闸门判据

| 判据 | 要求 |
|---|---|
| 用例数 | 不低于基线（92 / 35 / 16），只增不减；减少必须说明原因 |
| 构建 | 三端零错误。`vue-tsc` 报类型错即视为构建失败 |
| lint | 点单端 0 错 0 警 |
| 新增文件 | 必须进 Git；`data/`、`dist/`、`target/`、`node_modules/` 不提交 |

> **注意 CI 的已知盲区**：`ci.yml` 只跑点单端的 `test` + `lint`，**不跑 `build:h5` / `build:mp-weixin`**。所以点单端的构建失败必须在本地拦住——这是目前唯一靠人守的环节。

## 四、UI 定期更新专项

点单端与管理端是**两套独立设计语言**，各自演进，不要互相套用。

- 点单端：暖白纸 + 黑金，品牌体验优先，零第三方 UI 库
- 管理端：珍珠玻璃，信息密度优先，七层样式体系（见 `docs/DESIGN.md`）

### 4.1 点单端三真源（改 UI 的唯一入口）

| 文件 | 管什么 |
|---|---|
| `styles/tokens.scss` | 色 / 字阶 / 间距 / 圆角 / 阴影 / 动效时长 / 图标尺寸 / 留白 |
| `styles/common.scss` | 通用元件（`.card` `.card-dark` `.tag` `.stat-grid` `.row-item` `.skeleton` `.is-press`）+ 入场序列 `reveal-1..8` |
| `config/icon-set.json` | 图标名 + 色版登记 |

**页面和组件的 scoped 样式里不写死色值、字号、圆角、阴影。** 要改观感，先改这三个文件；如果某个值确实只属于一个页面，也要在 tokens 里起名再引用，不要在页面里就地写数字。

### 4.2 标准 UI 更新流程（六步，按序）

1. **定范围**：一次只改一个面。令牌级改动（换色/换字阶）影响全局，必须单独一轮。
2. **改真源**：令牌 → `tokens.scss`；通用观感 → `common.scss`；新图标 → `scripts/icons/<name>.svg` 母版 + `icon-set.json` 登记色版。
3. **生成产物**：`npm run assets:icons`（会自动清理已下线的孤儿 PNG）。
4. **过守卫**：`npm test` —— `tests/design-system.test.js` 会拦未登记图标名、缺失色版产物、残留 emoji。
5. **H5 目检**：`npm run dev:h5`，按 4.3 的检查表逐项确认。
6. **双端构建**：`npm run build:h5 && npm run build:mp-weixin`；小程序端另在开发者工具里真机预览一次（Tab 栏、安全区、固定底栏最容易出问题）。

### 4.3 视觉回归检查表

改完 UI 按这张表过一遍。**空态、长文本、深色卡、按压态**是历史事故高发区。

| 面 | 检查项 |
|---|---|
| 菜单页 `pages/index`（含订单/会员/我的 Tab 面板） | 商品卡列表图比例不变形（`aspectFill`）；空购物袋空态；长商品名不撑破容器；深色会员卡上金字的对比度；Tab 切换入场序列不叠动画 |
| 详情页 `pages/detail` | 详情大图容器比例（约 1.88:1）；规格选择器选中态；底部固定操作栏不被 `transform` 祖先带偏 |
| 结算页 `pages/checkout` | 取餐方式切换；备注输入；金额分级展示（小计/优惠/合计）；提交按钮 loading 态 |
| 登录页 `pages/auth` | 输入框聚焦态；错误提示复用 `.field-error`；键盘弹起时不被遮挡 |
| 全局 | 底部固定栏安全区；`hover-class="is-press"` 按压反馈；空 `<text>` 撑高（用 `min-height`，值 = 字号 × `$lh-body`）；同屏相邻卡片圆角不混用 `$r-md` / `$r-lg` |

### 4.4 管理端 UI 更新规则

1. **先复用再新建**：加组件前先看 `src/components/ui`（27 个）和 `business`（19 个）有没有能用的，别造同值类。
2. **提示文字复用既有类**：`.field-hint`（11.5px / `--ink-soft`）、`.field-error`（11.5px / `--red-text`）。不要另写 `.image-error` 这类同值规则。
3. **间距对齐** `.field` 的 `gap: 7px`；圆角/边框/背景沿用 `--r-sm` / `--line-strong` / `--input-bg`。
4. **图片填充用 `object-fit: cover`**，不用 `contain`（会留白，与点单端观感不一致）。
5. **窄屏同步**：`@media (max-width: 720px)` 内表单变单列，改完必须缩窗验证。
6. **改完跑** `npm run test:unit && npm run build`（`vue-tsc` 会抓模板类型错误）。

### 4.5 UI 红线（违反会直接出事故）

| 红线 | 后果 |
|---|---|
| 在 `<text>` 里放 Unicode 字形（☕ ✦ › ↗ ✓ ＋） | iOS/安卓/H5 三种粗细比例，且无法统一着色 |
| 把 class 写在自定义组件标签上靠它定位 | 宿主节点行为随基础库版本变，样式时灵时不灵 |
| 组件 scoped 样式用属性选择器（`[disabled]`） | 小程序端不生效，绑 class 代替 |
| 给含 `position: fixed` 后代的祖先加 `transform` | 成为包含块，底部固定栏跟着漂 |
| 前端 canvas 先压缩再上传 | 两次有损编码，清晰度不可逆下降（压缩只在服务端做一次） |
| 用 JS `input.click()` 触发文件选择 | 浏览器只认用户手势，报 `File chooser dialog can only be shown with a user activation`；用 `<label for>`，多个实例时 `for`/`id` 必须逐实例唯一 |

### 4.6 UI 迭代候选池（可直接排期的小改动）

| # | 改动 | 面 | 价值 |
|---|---|---|---|
| U1 | 商品卡骨架屏细化（现为统一 `.skeleton`） | 点单端菜单页 | 首屏观感，弱网体验 |
| U2 | 订单状态进程条微动效（下单 → 制作 → 可取餐） | 点单端订单面板 | 让状态变化可感知 |
| U3 | 会员权益卡与成长值可视化 | 点单端会员面板 | 提升复购意愿 |
| U4 | 管理端列表页统一空态插画 + 加载骨架 | 管理端 coffee/operation | 信息密度下的一致性 |
| U5 | 管理端 Dashboard 卡片入场序列收敛（现多处 GSAP 各自为政） | 管理端 | 动效可维护性 |
| U6 | 小程序端暗色模式适配（令牌先扩一组暗色变量） | 点单端全局 | 夜间下单场景 |

> 一次只挑 1 条，走 4.2 六步。**不要把两条 UI 改动塞进同一个提交**——令牌级改动的回归面太大，混做后出问题无法二分定位。

## 五、功能迭代候选池

按「不做的代价」排序。支付相关条目已剔除。

### P0 · 现在就该补（质量缺口，非新功能）

**P0-1 接口级集成测试（最优先）**

- 缺口：`@SpringBootTest` / `MockMvc` **全库零命中**。92 例全是单元测试，**没有一条端到端验证鉴权链路**。
- 风险：`SecurityConfig` 兜底 `denyAll()`，新增路径忘配即 403；JWT 双主体隔离（`member:` 前缀）目前只有单元级的 `JwtServiceTest`，没有真实请求穿过 filter chain 的验证。
- 落点：`src/test/java/com/hiddenwhite/integration/`
- 最小集（按价值排序）：
  1. 会员 token 打管理端接口 → 401/403
  2. 管理端 token 打点单端接口 → 401/403
  3. 无 token 访问 `/api/orders` → 401
  4. 越权读他人订单（`GET /api/orders/{id}`）→ 404/403
  5. 公开接口（`/api/products`、`/api/health`）正常放行
  6. 限流触发 → 429 且响应体与 `R` 同构
- 验收：CI 里能跑（需注意 `@SpringBootTest` 依赖真实 MySQL——建议用 H2 或在 CI 起 MySQL service，二者取其一并在本清单登记选择）。

**P0-2 积分 / 优惠券流水表**

- 缺口：`members.points`、`members.coupons` 是整数字段，**无任何流水记录**。消耗过程不可追溯，无法对账、无法退单回溯。
- 影响：一旦有用户质疑积分扣错，只有当前余额，没有依据。
- 落点：`database/init.sql` 新增 `member_points_log`（`member_id` / `change_amount` / `balance_after` / `reason` / `ref_order_id` / `created_at`），积分写入口改为「先记流水再更新余额」，同一事务。
- 验收：任一笔积分变动都能从流水反推出当前余额；`OrderService` 积分相关测试覆盖正向与回滚。

### P1 · 交付前必须补

**P1-1 点单端分包**

**P1-3 生产构建的后端地址探测**

- 已确认：`config/backend.js:122` 只有 `if (import.meta.env && import.meta.env.DEV) return '/api'` 短路开发态。
  非 DEV 构建会按 `config/backend-hosts.js` 的 4 个地址逐个做健康检查
  （`192.168.137.1` / `10.30.225.27` / `10.30.120.150` / `10.30.72.77`，均为内网）。

- 验收：生产构建产物中不出现内网 IP 字面量；无 `VITE_API_BASE_URL` 时首屏探测在固定时长内结束。

> 2026-10-26 改为「隐白咖啡 · 管理端」。`manifest.json` 的 Android 权限也已确认只剩

## 六、调试手册

### 6.1 已知坑速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 接口 404 | 常是进程没重启到新代码，不是代码没写 | 先确认监听进程的启动时间与命令行，再怀疑路由 |
| 8080 起来但行为不对 | IDEA 调试进程占着 8080 跑旧代码（命令行含 `-javaagent`，不热加载） | 另起端口（如 8081）跑新 jar 验证，别去动用户的调试会话 |
| 上传失败但无具体原因 | `spring.servlet.multipart.max-file-size` 小于业务上限，请求在容器层就被截断 | 容器上限必须**略大于** `hiddenwhite.image.max-bytes` |
| 图片传不上去 | 管理端手写了 `Content-Type`，丢了 boundary | 用 `api/http.ts` 的 `upload()`（刻意与 `post()` 分开实现） |
| 图片存到了奇怪目录 | 上传目录按「模块根」反推，不按进程工作目录 | 看启动日志打印的绝对路径；`ImageStorageService.root()` 是唯一入口 |
| 上传接口 500 且业务结果丢失 | `@OperLog` 切面序列化 `MultipartFile` 抛异常 | 已修为文件参数转摘要（文件名+大小+MIME）；新增文件参数要沿用 |
| 订单状态推进报 500 | 状态机抛 `IllegalStateException` 未映射 | 已映射 409（「订单已被别人推进」属可重试冲突） |
| 前端 `aspectFill` 裁掉了图 | 服务端目标比例与展示容器不一致，裁了两次 | 列表图 284×240、详情图 1200×636；改配置会让 `ImageProcessorTest` 失败 |
| 空 `<text>` 导致基线错位 | 空元素塌陷为 0 高 | 用 `min-height`，值按实际行高算（字号 × `$lh-body`） |
| 设计守卫测试失败 | 未登记图标 / 缺色版产物 / 残留 emoji | 按提示补 `icon-set.json` 或跑 `assets:icons` |

### 6.2 现象 → 路径

| 现象 | 排查顺序 |
|---|---|
| 点单端连不上后端 | 1) `/api/health` 直连是否通 → 2) `config/backend-hosts.js` 候选地址是否含当前网段 → 3) H5 控制台看探测结果 → 4) CORS（prod 下 `CORS_ALLOWED_ORIGINS` 留空 = 不放行任何跨域） |
| 数据不对 | 1) 定位是哪个端算的（价格/取餐号/首单减免一律后端算）→ 2) 查 SQL 是否漏了范围条件或用了 `DATE(col)` 导致索引失效 → 3) 查是否有「先读再整体覆盖写」的计数器（应写自增） |
| 全局样式改了没生效 | 1) 是不是写在了页面 scoped 里而不是 `tokens.scss` → 2) 小程序端是否忘了重新 build → 3) 是否有更具体的选择器压着 |
| 小程序白屏 | 1) 开发者工具清缓存重编 → 2) 看是否是 `transform` 包含块问题 → 3) 检查分包路径 |
| 管理端登录不了 | 1) 验证码是否过期（取出即失效）→ 2) 是否触发限流 429（30 次/分钟按 IP）→ 3) 种子账号密码 |

## 八、这份文档自己的维护规则

1. **基线数字变了就改第一节**，不要只在台账里记。第一节永远代表「当前真实状态」。
2. **候选池不是待办列表**：完成一条就从池里删掉，在台账里留痕。池子长期不动说明节奏断了。
3. **每季度重排一次优先级**，而不是不断往里加条目。池子越长越不会被执行。
4. **只有常态性、可循环的事才进这份文档**。一次性的评估结论（如历史上的健康检查报告）保留为快照，不再更新。
